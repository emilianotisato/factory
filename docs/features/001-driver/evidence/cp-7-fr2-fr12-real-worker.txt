## what else the run showed
- The hint was read and followed. Turn 2 ran `factory ctx refs foo`, the verb the reason names, and it failed with exit 127: `factory: command not found`. `factory` is not installed on this machine (`which factory`: none; no ~/.cargo/bin/factory). The hook resolved because the settings name the binary by its absolute path (AD-1309), but the hint and the pack's `# Lookup` name the bare `factory`.
  - qa-guide.md lists "`factory` installed" as a precondition of a real run, so on the owner's runs the verb resolves. This is a fact about the probe, not a driver defect, and it is not fixed here.
  - A driver started from an uninstalled build, such as `cargo run` or the target dir, leaves its workers with a hint they cannot follow.
- Claude Code prefixes the reason with "PreToolUse:Bash hook error:". Haiku read it as a block, not a crash ("Hook blocks grep here"), and asked whether factory is installed.
- AD-1304 (a build worker must Read its slice by range before its first Edit) is NOT confirmed by this run. The fixed prompt has no Edit, and a second real run with another prompt is out of bounds for this checkpoint. Unreached here; it is a check in the owner's A/B (qa-guide.md, FR-11 step 6).
