**Code-review fixes (2026-10-10).**
- `settle_dead` counted every death in the run and always wrote `BLOCK-{NN}02`, so after an answer one more death re-blocked the slice with a duplicate block `factory answer` could not reach, the id could clash with a builder's own block, and a kill mid-settle could give a capped slice a third worker (L2, Xc9). Deaths now count from the owner's last answer on the slice in `events.jsonl` order, the block takes the lowest free `BLOCK-NNkk` from 02, and the spawn loop blocks a capped slice instead of respawning it (AD-20001, AD-20002).
- An error out of `drive_inner` marked the run failed and dropped its live workers unkilled and unsettled, so they kept building with nobody watching (L8). A failing driver now kills and reaps its live workers through `Worker::kill` and settles each one `failed`, and a worker is in the table from the moment it spawns.
- The worker's stdout went through a tee thread in the driver, so a driver that died cut the stream (EPIPE) and the orphan was settled from a truncated record (L9). The stream file is now the worker's stdout itself, parsed when the process exits (AD-10006).
- `Worker::spawn` started the child before the `?`-checked row insert, so a database error left an orphan nobody killed (L15). The child is now killed and reaped when that insert fails.
- The env scrub removed every `CLAUDE_*`, `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_OAUTH_TOKEN` and the Bedrock and Vertex switches included, so a worker could run logged out or as another account (L17). `worker::KEEP_CLAUDE_VARS` and every `CLAUDE_CODE_USE_*` now pass through, while `CLAUDECODE` and the other session variables are still scrubbed (AD-10007).
- `assets/autonomy.md` told a worker to read a file whole, run the flaky rerun and push a block, all of which slice 13's hook refuses (Cn2). Lines 58, 67, 78 and 85, and lines 5 and 13 of `assets/contract-ci-fix.md`, now say what the hook enforces, edited in place so every `autonomy.md:NN` citation still points at the same line (AD-10004).
