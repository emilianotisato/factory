## 1. Why now

1. **The driver shells out to node for every board read and every tool verb.** `src/docs.rs:64-79` runs `node docs.mjs` through `Command`; the call sites in §8 run it 27 times between them, three of them `Docs::locate`. The two reads that matter, `status` and `preflight`, parse JSON back into `#[serde(default)]` structs so a tool upgrade cannot break the driver (`:109-127`); `gate` returns stdout and the rest return a raw `ToolOutput`. The writes the driver does by itself are frontmatter edits and markdown appends into files the tool owns (`scheduler.rs:1796,1743`). Two tools, two languages, one contract held together by defaults.
2. **Half of `docs.mjs` is drift machinery for derived state stored twice.** The index tables, the "Next free PRD number / Next free FR" counters, the slice tables between `<!-- docs:slices -->` markers and the status cells are all copies of what the folders already say. `render` (`docs.mjs:1152`), the counter checks (`:1025-1036`), `E-INDEX-MISSING-ROW` (`:998`), `W-PROSE-STATUS` (`:873`) and `check --fix` exist only to keep the copies in step. The driver pays for it too: `checkpoint.rs:813` and `closeout.rs:587` run `render --write` before their commits so the copies do not drift.
3. **The slice-log fragments cost the last run twice.** `docs log merge` refused a fragment at CP-4 and two more at the polish merge of PRD-001, each time over a title line or prose above the first `## ` heading (`docs.mjs:1612-1633`; [`retro.md`](../001-driver/retro.md) "Where I guessed"). The driver carries four workarounds for `agent-log.md` not existing when a vendored tool predates AD-503 (`commit.rs:394`, `checkpoint.rs:91`, `closeout.rs:108`, `cli/answer.rs:321`).
4. **Retro numbers are YAML in a markdown file nobody queries.** `closeout.rs:609` writes twelve keys into `retro.md` frontmatter; the only reader is `W-RETRO-FM`. The learning loop (PRD-001 §19) needs them in the metrics store next to the run they came from.

**Boundary.** This PRD ports the tool and changes the format. It does not change what the framework records or how a feature moves through `draft → ready → in-progress → shipped → archived`. The skills that call `docs.mjs` stay as they are until the FR-11 A/B is over (§7, §13).

## 3. FR-13 — The v3 layout: `project.toml`, `state.toml`, a frontmatter-only PRD header, feature-scoped FR ids

**Today.** The project declares itself in `docs/index.md` frontmatter (`framework`, `gate`, `inner`, `lanes`, `gate_parallel`, `checkpoint_every`, `prd_max_kb`, `slice_max_kb`; `docs.mjs:295 loadProject`). A feature's status lives in `prd.md` frontmatter (`number`, `slug`, `status`, `owns_fr`, `retired_fr`, `reviewed`), repeated as a cell in the index Live-features table, and repeated again as a `**Status**:` prose line in the PRD header. Each slice's `status`, `lane` and `depends_on` live in that slice file's frontmatter, which the driver edits in place (`scheduler.rs:1796 set_slice_status`, `:1821 set_frontmatter`). FR numbers are one global axis across features, with a "Next free FR" counter in the index (`docs.mjs:1025-1036`). `MAINTAINING.md` (2026-08-13) rejected a single central state file: it was a second board, hand-prose Notes drifted, moves needed manual GC, and every concurrent feature brought one merge conflict.

**Decisions taken 2026-10-11:**

- **`docs/project.toml` replaces the index frontmatter.** Keys: `framework = 3`, `gate`, `inner`, `lanes`, `gate_parallel`, `checkpoint_every`, `prd_max_kb`, `slice_max_kb`. Defaults when a key is absent, as `loadProject` applies them today (`docs.mjs:295-325`): `lanes` 1, `checkpoint_every` 2, `prd_max_kb` 120, `slice_max_kb` 30, `gate` and `inner` none. **`gate_parallel` has no default**: absent means nobody measured it and preflight says `judge`; a written `false` is an `ask` (`docs.mjs:1725-1726`). *(Corrected 2026-10-11 after review: an earlier draft gave it a default of `false`, which would have turned every unmeasured repo's `judge` into an `ask` at migration.)* `docs/index.md` stays as the human entry point: layout, status vocabulary, lifecycle, build order, retired numbers and the reference list, all prose. **It loses its frontmatter, the Live-features table, the Archived table and the two counters.** `factory docs status` with no argument prints that board from the folders. *(Accepted cost: a reader on GitHub no longer sees the board in `index.md`; they open the feature folders or run the tool. The owner reads the board in the cockpit anyway.)*
- **One `state.toml` per feature, at `docs/features/NNN-slug/state.toml`.** Holds `status` (the v2 vocabulary: `idea | draft | ready | in-progress | shipped | archived | retired`), `reviewed` (a date, absent until `/polish` sets it), `shipped` (a date, set by `ship`), and one `[slices.N]` table per slice with `status` (`pending | building | blocked | done`), `lane` and `depends_on`. Slice files keep their number in the filename (`slice-NN-subject.md`) and their title in the H1, nothing else machine-read. *(Why per feature and not central: MAINTAINING's four objections were all about one shared file. Per feature, the file lives and dies with its folder, archiving moves it, and two concurrent features never touch the same file. Accepted cost: one more file per feature; the board is a scan of N small files, which v2 already does over N `prd.md` frontmatters.)*
- **Only the tool writes `state.toml`.** `factory docs set NNN key=value…` with dotted keys (`status=ready`, `slices.3.status=building slices.3.lane=1`) is the one write path; it refuses unknown keys and values outside the vocabulary. The driver calls the same function in process (FR-18). Every write is a temp file plus rename in the feature folder, under the feature's advisory lock (`docs.lock`, the same one FR-14 uses), per DEC-3: with `lanes` ≥ 2 two workers set their own slice `done` at the same time, as the worker contract tells them to today (`assets/contract-slice.md:18`). *(Corrected 2026-10-11 after review: an earlier draft had no lock on state, on the claim that the driver was the one writer; the worker contract says otherwise.)* *(Rejected: letting workers or the owner edit the TOML by hand. Nothing stops them, but `check` reports a file that does not parse or a value outside the vocabulary, and the driver skips and reports a torn file rather than failing the run, as DEC-3 says.)*
- **The PRD header is frontmatter only.** `prd.md` frontmatter becomes `number`, `slug`, `title`, `type`, `created`, `author`, `summary`. `status`, `reviewed`, `owns_fr` and `retired_fr` leave the PRD (`state.toml` holds the first two; the last two are implied by feature-scoped ids). The prose header block (`**Type**`, `**Status**`, `**Created**`, `**Author**`, `**Owns FR range**`) goes; `summary` replaces the index Notes cell, the most valuable cell in v2's index, and `factory docs status` prints it. The `# PRD-NNN — Title` H1 stays for readers; the tool never reads it. *(Accepted cost: the `summary` is one YAML block scalar the author keeps current, as the Notes cell was. `check` warns when it is empty on a `ready` feature.)*
- **FR ids are feature-scoped.** Within a feature they are `FR-1`, `FR-2`, …; across features the reference is `PRD-NNN FR-n`. The global "Next free FR" counter goes, and with it `owns_fr`/`retired_fr`. A cut FR keeps its section, titled `FR-n — RETIRED (date)`, as the template already says. **Migration does not renumber prose** (FR-16): PRD-001 keeps FR-1…FR-12 and this PRD keeps FR-13…FR-19, because rewriting FR numbers inside hand-written prose, slices and archived folders is exactly the drift machinery v3 removes. Both are unique either way. *(Accepted cost: in this repo the first two PRDs read as one global axis and the third starts at FR-1. Stated in `index.md` prose at migration.)*
- **The archive is grandfathered: read, never written, never migrated.** `factory docs status` lists archive folders by scan and tells `retired` from `archived` by reading each folder's `state.toml` when it has one, else its v2 `prd.md` frontmatter `status`, as `computedStatus` does today (`docs.mjs:367`). `migrate` reads archive `retro.md` frontmatter once for `retros` rows (§6, §9). `check` keeps "archive is frozen" (FR-15). *(Corrected 2026-10-11 after review: an earlier draft said the archive was never read and that retired numbers came from folder names, which carry no status; today's retired list is a prose line in `index.md`, `docs.mjs:330`.)* The 18 archived features of `arca-api` and 15 of `icg-cloud` stay v2 files, frozen.

**Acceptance**: in a repo migrated by FR-16, `factory docs status` (no argument) prints every live feature with its status and summary, the archive count and the retired numbers, from `project.toml`, the `state.toml` files, the folder names and the archive folders' status alone; delete the board text from `index.md` and nothing the tool prints changes. `factory docs set 002 slices.3.status=building` rewrites `state.toml` atomically and `factory docs status 002 --json` reports the slice as building. `factory docs set 002 status=later` exits 2 with the vocabulary in the message.

## 4. FR-14 — The append-only log: `log.jsonl`, `log add`, `log show`

**Today.** Each worker writes a markdown fragment next to `agent-log.md` (`commit.rs:38 fragment_path`); the driver runs `docs log merge` at every checkpoint (`checkpoint.rs:207`, `commit.rs:387 fold_logs`), which refuses on an AD clash or on prose above the first `## ` heading (`docs.mjs:1612-1633`). AD and BLOCK ids are seeded per slice (AD-301 for slice 3) so parallel workers cannot clash, and `E-LOG-DUPLICATE` (`docs.mjs:936`) catches it when they do. The driver appends BLOCK entries (`checkpoint.rs:176`) and preflight AD entries (`cli/answer.rs:296 answer_ask`, a `### AD-n · preflight` entry below 100 since 2026-10-12) with `scheduler::append_under` (`:1743`); an answer is `answers::resolve` (`answers.rs:346`), which flips the BLOCK heading from `open` to `resolved` and inserts a `**Resolution (date):**` line. The owner's review appends `**Owner (date):** kept|changed` under each AD (`skills/factory-deliver/SKILL.md:38`).

**Decisions taken 2026-10-11:**

- **One `log.jsonl` per feature, append-only, one JSON object per line.** Fields: `id` (`AD-n`, `BLOCK-n`, `CP-n`), `kind` (`decision | block | answer | checkpoint | ask | review | note`), `ts`, `slice`, `flag` (`fyi | decide`, decisions only), `ref` (the id an `answer` or `review` points at), `verdict` (`kept | changed`, reviews only), `title`, `body` (markdown). The file replaces `agent-log.md` and the fragments; there is no rendered copy in the repo. *(Accepted cost: on GitHub the log reads as JSON lines. `factory docs log show NNN` renders today's markdown shape; the PR body carries the `decide` entries, as the polish worker already writes it. Rejected: committing a rendered `agent-log.md` next to the JSONL, because that is one more derived copy to keep in step, the exact thing §1 point 2 removes.)*
- **Only the tool appends, and it allocates the id.** `factory docs log add NNN --kind decision --slice 3 --flag decide --title "…" --body-file -` reads the body from stdin or a file, takes the feature's `docs.lock` (an advisory `flock` in the feature folder, DEC-3), reads the last id of that kind, appends one line with the next id, releases, and prints the id. Workers call it through Bash with the resolved binary path the driver puts in their contract (`paths::factory_command`, CP-7 of PRD-001). *(Why ids at append and not slice seeds: the seed existed to avoid clashes between workers writing files in parallel; a locked append cannot clash, so the seed, the clash check and the merge refusal all go. Accepted cost: an id no longer says which slice wrote it; the `slice` field and `log show` do.)*
- **`factory docs log show NNN [--decide] [--open] [--json]`** renders the log as markdown to stdout in today's `agent-log.md` shape (`## Decisions`, `## Blockers`, `## Checkpoints`, review lines under their AD). `--decide` keeps only `decide` decisions without a `review` entry, which is what `/factory-deliver` §3 reads; `--open` lists blocks without an `answer`. `--json` prints the entries as read.
- **The driver's own writes become log entries**: a checkpoint's BLOCK (`checkpoint.rs:176`) is `kind: block`; `factory answer` writes `kind: answer` with `ref` where `answers::resolve` edits the heading today; the preflight AD entry (`cli/answer.rs:296`) is `kind: ask`; a checkpoint record is `kind: checkpoint` with `slice` = the last covered slice. The owner's review (`/factory-deliver` §3) is `kind: review` with `ref` and `verdict`; the skill edit is part of FR-18's contract changes since that skill lives in this repo.
- **`check` on the log** (FR-15): every line parses; ids are unique and increase per kind; every `answer` and `review` points at an id that exists.

**Acceptance**: two processes run `factory docs log add 002 --kind decision …` concurrently 50 times each in the harness; `log.jsonl` holds 100 lines, `AD-1` … `AD-100`, no gaps and no duplicates. A body with a `#` title line and prose above its first heading is stored and rendered as written; nothing refuses it. `log show 002 --decide` lists exactly the `decide` entries with no review.

## 5. FR-15 — `factory docs`: the verb set in v3

**Today.** `docs.mjs` has sixteen verbs (`docs.mjs:2047-2104`): `check [--fix --strict]`, `doctor`, `status [--json]`, `lanes [set --env --setup]`, `log merge`, `preflight`, `render [--write]`, `init`, `new`, `slice`, `gate [set --inner --candidates]`, `ship`, `archive`, `renumber`, `vendor`, `hook [--here]`. `die()` exits 2 (`:1984`); `check` exits 1 on errors (`:2051`); `preflight` exits 0 pass, 1 refused, 2 asks pending (`src/docs.rs:115-127`). The interview kept `hook`, `lanes` and `renumber`; it cut `vendor`, and v3 makes `render`, `log merge` and `check --fix` meaningless.

**Decisions taken 2026-10-11:**

- **A `docs` subcommand on the binary** (`src/main.rs:19 Command`), verbs: `init`, `new`, `slice`, `status`, `preflight`, `gate`, `set` (FR-13), `log add|show` (FR-14), `ship`, `archive`, `renumber`, `lanes`, `check`, `doctor`, `hook`, `migrate` (FR-16), `retro` (FR-19). Exit codes as today: 0 ok, 2 refused with the reason on stderr, `check` 1 on errors, `preflight` 0/1/2. `--json` where v2 has it (`status`, `preflight`) with the same keys, so the `Status` and `Preflight` structs in `src/docs.rs:170-306` are the output contract, not just the input one.
- **`init`** writes `docs/project.toml`, `docs/index.md` (prose only), `docs/features/`, `docs/ideas.md`, `docs/archive/`. **`new <slug> --title`** allocates the next number as today (`docs.mjs:1251 allocateNumber`): the scan of `features/` and `archive/`, raised to the reservation in `<git-common-dir>/docs-next-number`, which it then bumps, so two worktrees of one repo cannot claim the same number; that file is untracked and is not the index counter *(corrected 2026-10-11 after review: an earlier draft said "no counter")*. It writes `prd.md` from the v3 scaffold and `state.toml` with `status = "draft"`. **`slice NNN <subject> [--depends a,b]`** writes `slice-NN-subject.md` and the `[slices.N]` entry. **`renumber NNN MMM`** renames the folder, sets `number` in the PRD frontmatter and rewrites the folder path and `PRD-NNN` in every markdown file under `docs/` **outside `archive/`**, and prints the archive files it left alone. Today's `walkMd(p.docs)` (`docs.mjs:1890-1898`) rewrites archive files too, which the frozen rule and the pre-commit hook then refuse. *(A change from today, decided 2026-10-11 after review.)* **`lanes [set N] [--env] [--setup]`** reads and writes `project.toml` `lanes` and manages `lanes/` as today (`docs.mjs:1504`).
- **`gate [set <cmd>] [--inner] [--candidates]`** reads and writes `project.toml` `gate` and `inner`; candidates come from `docs.mjs:483 gateCandidates`, ported.
- **`ship NNN`** refuses while any slice is not `done`, as today (`docs.mjs:1797`); sets `status = "shipped"` and `shipped = <date>`. **`archive NNN`** has the same refusals, moves the folder to `archive/` and sets `archived`. Neither touches `index.md`.
- **`check`** keeps: `project.toml`, every `state.toml` and every PRD frontmatter parse with the required keys; every slice file has a `[slices.N]` entry and the reverse; `depends_on` names existing slices and has no cycle (`docs.mjs:1106 findCycle`); links resolve (`E-LINK-BROKEN`, `:1066`); staged modifications under `archive/` (`E-ARCHIVE-MODIFIED`, `:1050`); legacy planning dirs and second boards (`W-LEGACY-DOCS`, `:1079`; `SECOND_BOARD_NAMES`, `:35`); size ceilings from `project.toml`; `W-NO-QA-PLAN`; the log rules in FR-14; an empty `summary` on a `ready` feature. **Drops**: every index-table and counter code (`E-INDEX-MISSING-ROW`, `E-COUNTER-STALE`), `W-PROSE-STATUS`, `W-RETRO-FM`, and `--fix`, because v3 stores nothing derivable. `--strict` goes with them; a warning is a warning.
- **`doctor`** prints one of `v3`, `v2 (run factory docs migrate --dry)`, `v1`, `not on the framework`, plus what `check` would say; it never writes. **`preflight NNN`** keeps the four buckets (`refuse`, `ask`, `judge`, `ok`), the exit codes and the branch block, and reads `project.toml` and `state.toml` instead of frontmatter. It never sees a v2 repo: the shim (FR-17) sends every v2 call to `docs.mjs`, whose own preflight runs. *(Corrected 2026-10-11 after review: an earlier draft had native preflight refuse v2, which the shim makes unreachable; the driver's refusal is `Docs::open` in FR-18.)*
- **`hook [--here]`** installs or prints the pre-commit body of FR-17, with today's `core.hooksPath` behaviour (`docs.mjs:1949`).

**Acceptance**: `factory docs --help` lists the seventeen verbs and nothing else; in a v3 repo `factory docs vendor`, `render` and `log merge` exit 2 with "removed in v3" and a pointer (in a v2 repo the shim passes them to `docs.mjs`, FR-17). In the v3 fixture every verb above runs green in `cargo test` with the exit code stated. `factory docs status 001 --json` in the fixture deserializes into `docs::Status` with the same field values the v2 fixture test asserts today (`tests/docs.rs:21-34`).

## 6. FR-16 — `factory docs migrate [--dry]`: v2 → v3, one shot per repo

**Today.** `doctor` (`docs.mjs:661`) reports drift and lists the `upgrades/vN.md` notes newer than the repo's version (`:726 upgradeDocs`); nothing moves a repo between versions by itself. Nothing reads v3. Twelve repos are v2 (§2); their live features hold 16 `retro.md` files in total, about 120 archived folders, and `agent-log.md` files whose shape `docs.mjs:263 parseAgentLog` parses for `### AD|BLOCK|CP` headings and `**Review:**` lines; it does not read `**Owner (date):**` lines, and any `#` or `##` heading ends the current entry (`:287`).

**Decisions taken 2026-10-11:**

- **`factory docs migrate --dry` prints the plan and writes nothing**: every file it would create, rewrite or delete, and every `retros` row it would insert, then exits 0. **`factory docs migrate` refuses when `git status --porcelain -- docs/` is not empty**, so the whole migration is one reviewable diff and the undo is `git checkout -- docs && git clean -fd docs`. It does not commit. *(Why no backup or `--undo`: git already holds every byte it changes; a second undo path is machinery with no evidence. The one thing git does not hold is the `retros` rows, so those are written with `INSERT OR REPLACE` keyed on `(repo, feature)`, and a re-run after an undo lands on the same rows.)*
- **What it rewrites, per repo**: `index.md` frontmatter → `project.toml` (same keys, same values; missing keys get the FR-13 defaults); `index.md` loses its frontmatter, Live-features table, counters and Archived table, keeps all other prose, and gets one line under Build order saying FR numbers in pre-v3 PRDs keep their global values. **Per live feature**: `prd.md` frontmatter → the FR-13 keys (`title` from the H1, `type`/`created`/`author` from the prose header lines when present, `summary` from the index Notes cell), the prose header block removed; `status` and `reviewed` → `state.toml`; every slice file's frontmatter → its `[slices.N]` entry, then removed from the slice file; `agent-log.md` → `log.jsonl` through the ported `parseAgentLog` extended with one match each for `**Owner (date):**` and `**Resolution (date):**` lines, with `Review:` lines as `flag`, Owner lines as `review` entries, Resolution lines as `answer` entries, any text outside an entry kept as `kind: note` with the raw markdown as `body`, and `agent-log.md` deleted *(corrected 2026-10-11 after review: an earlier draft said today's parser already read Owner lines)*; `retro.md` frontmatter → one `retros` row (FR-19) and a `## Numbers` table rendered under the retro's H1 from the same values, the frontmatter removed. **Archive folders are read for `retros` rows and never written.**
- **It never renumbers FRs, rewrites prose references to `docs.mjs`, or edits `CLAUDE.md`/`AGENTS.md`.** Those are the owner's one-line edits after the dry run. *(Accepted cost: a migrated repo's `index.md` lifecycle prose still says `docs ship <NNN>`; the owner fixes the wording or leaves it.)*
- **Owner repos migrate only on the owner's go, after the A/B** (§7). The build proves migration on a copy of this repo's own `docs/` (the v2 fixture) and on the PRD-001 folder, never on the owner's working tree; this repo itself is migrated by the owner after the merge, in its own commit (§13).

**Acceptance**: in the harness, `factory docs migrate --dry` on a v2 fixture built by `node docs.mjs` leaves `git status` empty and prints a plan naming `project.toml`, each `state.toml`, each `log.jsonl` and the retro rows; `factory docs migrate` then produces a tree where `factory docs check` is clean, `factory docs status 001 --json` reports the same slices, statuses, lanes, dependencies, decisions count and `decide` ids the v2 `status --json` reported before, every AD/BLOCK/CP from `agent-log.md` is present in `log show` with its body and review line, and the retro row matches the old frontmatter. `git checkout -- docs && git clean -fd docs` then restores a tree where `node docs.mjs check` is clean, and a second `migrate` reproduces the same files byte for byte and the same rows in every column but `written_at`. Run on a copy of this repo's `docs/` with PRD-001 (145 decisions, 7 checkpoints, 1 block, 13 slices): the same invariants hold.

## 7. FR-17 — Coexistence: the routing shim and the pre-commit hook body

**Today.** The skills, the owner's global hook and the driver all name `docs.mjs`. `Docs::locate` (`src/docs.rs:35`) prefers a vendored `.docs/bin/docs.mjs` then `~/.claude/skills/feature-docs/bin/docs.mjs`; `hookBody` (`docs.mjs:1932`) does the same. The FR-11 A/B of PRD-001 is running now on `icg-cloud` and `arca-api` with `/deliver` and `docs.mjs` as they are.
