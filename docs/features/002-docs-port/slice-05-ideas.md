## Tasks

### 1. `idea add`, with no lock and no clash — high — blocked by: —
**Source**: §10 FR-20: "**One markdown file per open idea, at `docs/ideas/YYYY-MM-DD-slug.md`.** The filename stem is the id; the date is the day it was added; the slug comes from the title, at most 50 characters. YAML frontmatter, as `prd.md` has: `title` (required), `state` (`open | owed`, required…), `added` (date, required), `origin` (optional…), `retrigger` (optional…), `priority` (optional, only `high`; absent is normal)." "**`factory docs idea add --title "…" [--state owed] [--origin …] [--retrigger …] [--priority high] --body-file -`** writes the file and prints the id. It creates the file with `O_EXCL`; on a name clash it tries `-2`, `-3`, … so two concurrent adds of the same title give two files. No lock, since no shared file is written. It creates `docs/ideas/` when missing."

`src/docs/ideas.rs` (new) and one `idea` arm in `src/cli/docs.rs` with `add | list | drop` below it. `fn slug(title) -> String`: lowercase, every run of non-alphanumerics to one `-`, trimmed of `-`, cut to 50 characters on a char boundary and trimmed again; an empty slug refuses (exit 2). `fn add(root, Idea) -> Result<String>`: `create_dir_all("docs/ideas")`, then `OpenOptions::new().write(true).create_new(true)` on `<today>-<slug>.md`, and on `AlreadyExists` the same with `-2`, `-3`, … until one opens. The file is the frontmatter (keys in the order above, absent ones omitted) and the body read from `--body-file` (`-` is stdin), ending in one newline. `--state` defaults to `open`; any other value than `open`, `owed` (and `high` for `--priority`) refuses before anything is written. Print the id alone on stdout, as `log add` prints its id.

The trap: a `-2` suffix pushes a 50-char slug to 52. The 50-char limit is on the slug from the title; the suffix goes after it, and `check` (task 6) must accept a stem ending in `-N`.

**Acceptance:** `tests/docs_ideas.rs`: two child processes each run `idea add --title Same --body-file -` twenty times at once, and `docs/ideas/` ends with forty files, every one parsing with `title "Same"`; a 70-char title gives a slug of at most 50 chars; `--state later` exits 2 and writes no file; a title holding `"` round-trips through `idea list --json`, and one holding both `"` and `'` exits 2; `idea add` in a repo with no `docs/ideas/` creates it.

### 2. `idea list [--json]` — high — blocked by: 1

### 3. `idea drop <id> --because`, one path in one commit — high — blocked by: 1
**Source**: §10 FR-20: "**`factory docs idea drop <id> --because "…"`** deletes the file and commits that one path, `git commit -m "docs: drop idea <id>" -m "<because>" -- docs/ideas/<id>.md`, so the reason lives in `git log -- docs/ideas/`. A pathspec commit leaves the rest of the tree as it is. It refuses an id that does not exist or a file with unstaged edits." §10: "**A file in `docs/ideas/` means the idea is open. There is no `graduated` or `dropped` state; leaving is deleting.**"

`fn drop(root, id, because) -> Result<()>`: refuse (exit 2) when `docs/ideas/<id>.md` is missing, when `--because` is empty, and when `git status --porcelain -- <path>` prints anything, which covers unstaged edits, staged edits and an untracked file; then `fs::remove_file` and the exact `git commit` above. The id is the stem; accept `<id>.md` too.

The trap: an idea added and never committed is untracked, so the pathspec commit has nothing to record and git exits 1. The PRD names only "unstaged edits"; refuse the untracked file with "not committed yet: delete it by hand", since there is no history to put the reason in.

**Acceptance:** with one committed idea, a staged unrelated `a.txt` and an unstaged edit to `docs/index.md`: `idea drop <id> --because x` exits 0; `git show --name-status HEAD` lists exactly `D docs/ideas/<id>.md` and the body holds `x`; `a.txt` is still staged and `docs/index.md` still modified. `idea drop nope --because x` exits 2; an idea with an appended line exits 2 and stays on disk; a freshly added, uncommitted idea exits 2.
