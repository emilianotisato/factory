## Tasks

### 1. `log.jsonl`, the entry and `log add` — high — blocked by: —
**Source**: §4 FR-14: "One `log.jsonl` per feature, append-only, one JSON object per line. Fields: `id` (`AD-n`, `BLOCK-n`, `CP-n`), `kind` (`decision | block | answer | checkpoint | ask | review | note`), `ts`, `slice`, `flag` (`fyi | decide`, decisions only), `ref` (the id an `answer` or `review` points at), `verdict` (`kept | changed`, reviews only), `title`, `body` (markdown)." "Only the tool appends, and it allocates the id. `factory docs log add NNN --kind decision --slice 3 --flag decide --title "…" --body-file -` reads the body from stdin or a file, takes the feature's `docs.lock`…, reads the last id of that kind, appends one line with the next id, releases, and prints the id." The slicing addition: "an optional `phase` field (`preflight | slicing | checkpoint | polish | pr | ci`) on any entry… `decision` and `ask` share the `AD` sequence."

`src/docs/log.rs` (new): `Entry { id: Option<String>, kind, ts, slice: Option<u32>, flag: Option<Flag>, #[serde(rename = "ref")] reference: Option<String>, verdict: Option<Verdict>, phase: Option<String>, title: String, body: String }`, `Serialize + Deserialize`, absent options skipped on write. `pub fn add(dir, entry) -> Result<Option<String>>`: take `state::lock(dir)`, read `log.jsonl` (created on the first append), allocate the next id of the entry's sequence (`decision` and `ask` → `AD`, `block` → `BLOCK`, `checkpoint` → `CP`, the highest `n` read plus one), stamp `ts`, append one line in one write, release, return the id. `answer`, `review` and `note` get no id. `pub fn entries(dir) -> Result<(Vec<Entry>, Vec<(usize, String)>)>`: every parsed line in file order, plus the lines that do not parse, as `events::scan` returns them. Validate before taking the lock, and refuse with exit 2: `flag` on anything but `decision`; `verdict` on anything but `review`, and a `review` without one; `ref` missing on `answer` or `review`, or naming an id the log does not hold; `phase` outside the vocabulary; a `checkpoint` without `--slice` (prd §4: "a checkpoint record is `kind: checkpoint` with `slice` = the last covered slice"). `src/cli/docs.rs`: `log add NNN --kind --title [--slice] [--flag] [--ref] [--verdict] [--phase] [--body-file <path|->]`, printing the id (nothing for an id-less kind).

The trap: the `ref` check reads the log, so it runs inside the lock with the allocation, not before it. A ref read before the lock can name a BLOCK another process is writing at that moment.

**Acceptance:** unit tests in `src/docs/log.rs`: in an empty feature folder `add` decision, ask, block, checkpoint, decision returns `AD-1`, `AD-2`, `BLOCK-1`, `CP-1`, `AD-3`, and `log.jsonl` has five lines that each parse; an `answer` with `ref: BLOCK-1` returns `None` and stores the ref; an `answer` with `ref: BLOCK-9`, a `decision` with `verdict`, a `block` with `flag`, and a `checkpoint` with no slice each refuse and leave the file unchanged; a log whose last line is torn (no newline, half a JSON object) gets the next entry on its own line, and `entries` returns the good lines plus one skipped line.
