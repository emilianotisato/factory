Four repos report errors today: Nightwatch in prokeycloud and cody-agent, Sentry in nycase and prokeycloud_onprem, Flare configured in prokeycloud. Shape, as `gate`: `project.toml` names a script per source (`[pull.sentry] cmd = "scripts/factory/pull-sentry.sh"`, plus noise thresholds: minimum count, minimum users, seen in the last N days); the script prints one JSON object per issue (`source`, `fingerprint`, `title`, `level`, `count`, `users`, `first_seen`, `last_seen`, `url`, `culprit`, `environment`, `release`); the binary checks the contract and upserts rows into a `bugs` table in the metrics store, keyed by repo, source and fingerprint. **Never in the repo**: production data can carry emails, payloads and tokens, so rows stay local, counts refresh with no commits, and `drop` is a status column the next pull respects. `promote <id>` writes a normal idea file (PRD-002 FR-20) with only the title, the culprit line and the tracker link, `origin: sentry`. **Needs a companion skill to build the puller** (working name `/bugs-setup`), the way `/verify-app` and `/gate` build a project's automation: it finds the tracker in `composer.json` or `package.json`, asks which `.env` key holds the token, writes `scripts/factory/pull-<source>.sh` and the `[pull.<source>]` block, and runs `factory bugs pull --check` until the output fits the contract. The binary and the skill ship together; without the skill each repo's script is hand work. The token stays in `.env`. Gotchas: Nightwatch has an MCP server with OAuth browser login and no REST API found (https://nightwatch.laravel.com/docs/mcp-server, checked 2026-10-12), so a headless script cannot call it yet; Sentry has `/api/0/projects/{org}/{project}/issues/` with a token. Prove it on nycase or prokeycloud_onprem first. Cost: a local list is per machine. Brainstormed 2026-10-12; named `bugs` over `incidents` (ops outages), `issues` (GitHub) and `signals` (vague).
