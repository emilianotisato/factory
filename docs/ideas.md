# Ideas Inbox

Loose one-liners for things not yet worth a PRD. Cheap to add, cheap to drop.

**Rules**
- One line per idea. Enough to remember *what* and *why*, no more.
- No design, no scope, no tasks here — that's what a `features/{NNN}/prd.md` is for.
- When an idea earns real work: `/prd` → new `features/` folder, then delete the line here (or strike it).
- Not a backlog with priorities. Just a catch net so ideas stop dying in chat scrollback.
- A line cut from a PRD keeps its recon — say which PRD dropped it, when, and why, so a future PRD doesn't redo the research.

## Open

- **Codex or Cursor as build workers.** Different flags and stream; no evidence yet they are cheaper for slice work. Left out of PRD-001 (2026-10-09) until the metrics store can compare per-worker cost.
- **Decompose polish into driver-run steps.** Polish is the largest token line after the build; PRD-001 keeps it as one `claude -p` worker so the whole loop ships first. Revisit after the first A/B run with the per-worker numbers.
- **Typed lookup layer for `factory ctx` (LSP or SCIP).** gopls, rust-analyzer, phpactor or PHPantom, tsserver with the Vue plugin, held by the driver and fed file changes after each slice. Left out of PRD-001 (2026-10-09): 6–69 s cold and 0.3–3 GB per server, intelephense licence, Vue forwarding client, and the one controlled study found LSP cost more tokens on Opus and Sonnet. Open only if FR-8 shows `def` and `refs` still heavy after FR-12. Recon: `features/001-driver/ctx-research.md` §3–4.
- **Jev (TypeSafe System One) as a picker in `factory ctx` or the driver.** Non-generative Choice/Score/Noul API, about 300 ms from here, $0.042 per million input tokens. Assessed and parked 2026-10-09: nothing to disambiguate in `def` (91.2% single hit), Jev-scored window selection for reads missed the edited lines 30% of the time at 64% of bytes kept, block auto-answer lost to "pick the recommended option" (85.0% against 88.2%). Re-open only if FR-8's `followup_reads` shows reads after `ctx` above 30% of `ctx` calls, and then on public code until the clients consent in writing (TypeSafe's MCA puts the consent duty on the customer). Recon: `features/001-driver/ctx-jev-research.md`.
- **Uncle Bob's quality tools as gate tiers or polish inputs.** Check github.com/unclebob for CRAP, mutation, DRY and UML analysis. The current multi-language set is `crapper` (CRAP scores), `mutator` (mutation testing) and `dryer` (duplication), all Python, pushed 2026-10. The first two cover Clojure, Java, Go, TypeScript, Rust and Python; `dryer` has no description yet. All three write one snapshot that `uml-viewer` (Clojure/Quil, live class diagrams from EDN) reads. Why: a CRAP or mutation floor could catch the under-tested code polish reviewers miss. Gap: no PHP listed, but Uncle Bob says adding a language is easy, since the tools are built to be extended, so we can contribute PHP support ourselves when we get to it. Older per-language repos: `crap4go`, `mutate4go`, `dry4go`, `crap4java`, `mutate4java`, `dry4java`, `crap4clj`, `clj-mutate`, `dry4clj`, `scrap` (speclj spec refactoring), and `negative-test-experiment` (testing discipline × CRAP, then mutation). Added 2026-10-10, not assessed yet.
- **Batch `def` lookups in the pack's recon.** `Recon::of` in `src/pack.rs` calls `def::find` once per symbol, and each call walks the repo again. One walk that collects every wanted symbol would cut pack build time on large repos. Parked from PRD-001 polish (2026-10-10): correct today, only slow, and the pack is built once per worker.
- **Pre-push guard for the driver's own git calls.** The global `~/.config/git/hooks/pre-push` guard is active only under Claude Code (`CLAUDECODE=1`). The driver never sets it for its own git calls, so the guard is off for the gate, lane setup and hooks that the driver runs. Workers already cannot push (hook deny, AD-10001), and the driver pushes only the feature branch (AD-30009). This would add a third layer. Parked from PRD-001 polish (2026-10-10).
- **Persist CI rerun rows across a driver restart.** AD-30008 keeps the stale rerun rows in memory, so a driver restarted mid-watch forgets which red checks were rerun. A `links` field on the `CiRerun` event would let a resumed watch rebuild the set. Parked from PRD-001 polish (2026-10-10): the run's in-flight status already covers most of the case.
- **Run the CI checks locally before the push (`nektos/act` or similar).** `act` runs a GitHub Actions workflow in Docker on this machine; `gh act` is the same as a `gh` extension. Why: each CI fix round costs a push plus minutes of waiting, and PRD-001's one red round (2026-10-11) was a test race that the local gate never showed. Check two things first: how far act's runner images differ from GitHub's, and whether a cheaper CI-shaped local gate (fewer cores, cold cache) catches the same class. Added 2026-10-11, not assessed yet.
- **Block worker pushes to a remote with its own `pushurl`.** AD-10001's push-off env rewrites push URLs with `pushInsteadOf`, which git skips for a remote that sets `remote.<name>.pushurl`. Adding a second `pushurl` through the env does not help, since git pushes to every one listed. Today the deny rules and the hook still stop a literal `git push`; only a push from a script or alias gets through. Options to assess: wrap `git` on the worker's `PATH`, or a `pre-push` hook that refuses while `FACTORY_LANE` is set. Parked from the PRD-001 owner review (2026-10-11).
