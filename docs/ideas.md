# Ideas Inbox

Loose one-liners for things not yet worth a PRD. Cheap to add, cheap to drop.

**Rules**
- One line per idea. Enough to remember *what* and *why*, no more.
- No design, no scope, no tasks here — that's what a `features/{NNN}/prd.md` is for.
- When an idea earns real work: `/prd` → new `features/` folder, then delete the line here (or strike it).
- Not a backlog with priorities. Just a catch net so ideas stop dying in chat scrollback.
- A line cut from a PRD keeps its recon — say which PRD dropped it, when, and why, so a future PRD doesn't redo the research.

- **Claude Code's advisor tool for workers.** Source: [code.claude.com/docs/en/advisor](https://code.claude.com/docs/en/advisor). The worker's model consults a stronger advisor model at decision points. Claude decides when, with no cap and no way to force a call. Experimental, Anthropic API only. Why: a cost and quality lever per role. Run builders on Sonnet with an Opus advisor, or give fix and polish workers an advisor, and compare them as an A/B arm. Recon: (1) Set it per worker with `--advisor <model>` (hidden from `--help`) next to `--model` and `--effort` in `src/worker.rs`, or `advisorModel` in the worker's `<session>.settings.json`. A user-level `advisorModel` reaches workers too, so the driver should set it explicitly either way. (2) The advisor must rank at or above the worker's model: Opus 5.5 workers accept only Opus 5+ or Fable. The API drops a refused pairing silently, so check the stream to see that it ran. (3) Each call reads the whole transcript uncached, at the advisor's rates. Builders peak at 150–170k context, so one call can cost more than several turns. (4) It counts toward subscription limits, and Fable bills to usage credits. Check whether the stream's usage and `factory report` see advisor tokens; the API reports them separately. (5) Subagents inherit it. (6) It stays off when feature-flag fetching is off (`DISABLE_TELEMETRY`) or with `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1`. The worker env scrub drops every `CLAUDE_*` outside `KEEP_CLAUDE_VARS`, so that switch must come through the settings file's `env` or a lane's env. Added 2026-10-12, not assessed yet.
- **Cross-repo ideas scanner: `factory ideas --json` plus an `/ideas` skill.** From one session, the owner sees the open ideas of every framework repo and picks the next PRD. The binary scans configured roots, dedupes by git common dir (icg-cloud's `wt-a`, `wt-b`, `wt-base` worktrees would otherwise count it four times), and prints rows with `project`, `repo`, `id`, `title`, the first sentence, `state`, `origin`, `added`, `age_days`, `retrigger`, `priority` and the body length, plus per project its in-flight PRDs, next free number, branch and last commit date. Sorting and filtering are mechanical; the judgment happens in the skill, with the owner. The handoff prints `cd <repo>` and a ready `/prd … --from-idea <id>` prompt, because a PRD needs a session in its own repo. Default output stays short (about 500 ideas would be ~60k tokens in full); `show <id>` prints one body. Brainstormed 2026-10-12; it reads PRD-002 FR-20's `idea list --json` per repo, with a best-effort `ideas.md` read flagged `"format": "v2"` for repos not migrated yet. Read-only in v1; triage (drop, merge) waits for evidence it is needed. Reads `factory bugs` rows too (next line): both by default, `--ideas` or `--bugs` to narrow, each row tagged `"from": "idea"|"bug"`.
- **`factory bugs pull | list | drop | promote`: production errors as a local bug list.** Four repos report errors today: Nightwatch in prokeycloud and cody-agent, Sentry in nycase and prokeycloud_onprem, Flare configured in prokeycloud. Shape, as `gate`: `project.toml` names a script per source (`[pull.sentry] cmd = "scripts/factory/pull-sentry.sh"`, plus noise thresholds: minimum count, minimum users, seen in the last N days); the script prints one JSON object per issue (`source`, `fingerprint`, `title`, `level`, `count`, `users`, `first_seen`, `last_seen`, `url`, `culprit`, `environment`, `release`); the binary checks the contract and upserts rows into a `bugs` table in the metrics store, keyed by repo, source and fingerprint. **Never in the repo**: production data can carry emails, payloads and tokens, so rows stay local, counts refresh with no commits, and `drop` is a status column the next pull respects. `promote <id>` writes a normal idea file (PRD-002 FR-20) with only the title, the culprit line and the tracker link, `origin: sentry`. **Needs a companion skill to build the puller** (working name `/bugs-setup`), the way `/verify-app` and `/guardrails` build a project's automation: it finds the tracker in `composer.json` or `package.json`, asks which `.env` key holds the token, writes `scripts/factory/pull-<source>.sh` and the `[pull.<source>]` block, and runs `factory bugs pull --check` until the output fits the contract. The binary and the skill ship together; without the skill each repo's script is hand work. The token stays in `.env`. Gotchas: Nightwatch has an MCP server with OAuth browser login and no REST API found (https://nightwatch.laravel.com/docs/mcp-server, checked 2026-10-12), so a headless script cannot call it yet; Sentry has `/api/0/projects/{org}/{project}/issues/` with a token. Prove it on nycase or prokeycloud_onprem first. Cost: a local list is per machine. Brainstormed 2026-10-12; named `bugs` over `incidents` (ops outages), `issues` (GitHub) and `signals` (vague).
