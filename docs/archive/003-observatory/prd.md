# PRD-003 — Observatory: measure, experiment and correct factory runs

**Split from / Related**: PRD-001 [`retro.md`](../001-driver/retro.md) § "FR-11 — A/B, arca-api" and its Correction and Next sections; PRD-001 §10 FR-8 (the store this extends) and §13 FR-11 (the A/B this replaces as the measuring method); PRD-002 FR-19 (the `retros` table, see §11). The learning loop from the 2026-10-09 brainstorm is deliberately a later PRD (§8 OPEN-3).

---

## 1. Why now

The owner decided on 2026-10-12, after the two A/B rounds, to switch fully to `factory` and improve it one PRD at a time: no more A/B against the old `/deliver`, experiments are knob changes measured by the store. Two things broke on the way there, and one thing is missing for that plan to work:

1. **`factory report` under-counted run B twice.** The polish worker spawns its own subagents (a UX review, a security review, a test classification), and their tokens never reach the worker row: `finish_worker` takes the stream's `result` event (`src/stream.rs:356-371`, `src/db.rs:434-467`), whose usage covers the worker's own messages only. Missed: 2,294,981 weighted on arca-api, 2,052,906 on icg-cloud. Run B's ratio moved from 76.2% to 86.4% of run A on arca-api, past a bar the retro had already graded (`001-driver/retro.md` § Correction). A number the owner used to grade a pass bar was wrong by 13%.
2. **Every retro's numbers were a hand job.** PRD-001's own retro and both A/B write-ups were produced with `measure.py` from the old skill family plus a scratch `weigh.py`, one session of work each, because `factory report --per-worker` prints no token columns at all (`src/cli/report.rs:192-216`) and nothing writes a numbers table into `retro.md` beyond twelve frontmatter keys (`src/closeout.rs:48-62`).
3. **A knob change that lowers quality would go unnoticed.** The knobs the owner wants to turn next (model and effort per role, pack size) can cut quality, and the store has no quality figure per run: polish findings are never parsed (only the `STATUS` line is, `src/stream.rs:126-141`), decisions are counted by `docs status --json` into a struct no driver path reads (`src/docs.rs:270-276`; a test asserts it, `tests/docs.rs:34`), CI red rounds are events with no report key. The knobs a run used live only in `~/.config/factory/config.toml` at the time of the run (`src/config.rs:69-101`), which no repo holds, so a run's variant is not reconstructible a week later.

This PRD builds the eyes: complete counts (FR-21), what the context is made of (FR-22), the knobs a run used (FR-23), mechanical quality signals (FR-24), and a retro the binary drafts (FR-25). It turns no knob, grades nothing with a model, and does not learn: those come after there are measured runs to learn from.

## 2. Blast radius

- **The metrics store** (`~/.local/share/factory/factory.db`): schema version 1 → 2 (`src/db.rs:15`), added columns and guarded `ALTER`s in the existing style (`src/db.rs:257-267`), no rewrite. Old rows keep nulls; `report` and `retro` print `—` for them. PRD-002 FR-19's `retros` table moves from v2 to v3 (§11).
- **The polish contract and the `/polish` skill**: one new return line (FR-24). A polish worker that omits it produces nulls, never a failed run. The skill lives in the old family at `~/.claude/skills/polish/SKILL.md` until PRD-002 ports it; the line is added there now.
- **The driver's ship step** (`src/closeout.rs:575-590`): after `fill_retro`, it now also writes a section into `retro.md`, a file the polish worker writes prose into (`assets/contract-polish.md:21`). The driver writes after polish exits, between markers it owns.
- **Config**: a new project file `docs/project.toml` is read when present (FR-23). PRD-002 owns the same file later; its keys must coexist (§11).
- **Worker transcripts** under Claude Code's projects dir are read after a worker exits (FR-21). Read-only. A missing dir means no subagents.
- **Token cost**: near zero. Everything here runs in the driver. The one worker-side change, the `FINDINGS` line, is a few output tokens per polish.

## 3. FR-21 — Count what a worker spawns

**Today.** The worker row's tokens come from the stream's `result` event (`src/stream.rs:356-371` → `src/db.rs:434-467`). Verified 2026-10-13 on arca-api run B's polish worker `ddbb0927` (run `024-20261012-e894`): `result.usage` weighs 1,948,573; the worker's transcript plus its four `subagents/*.jsonl` weigh 4,243,554. The driver's own copy of the stream, `runs/<id>/workers/<session>.jsonl` (`src/worker.rs:243-246`), does carry the subagent messages: 403 of its 1,276 lines have `parent_tool_use_id` set, and the collector takes every assistant and user line without looking at that field (`src/stream.rs:292-355`). On those lines `input_tokens` and the two cache fields match the transcript exactly, but `output_tokens` is an early snapshot: 6 against 508, 16 against 165, on the same message ids. Summing the stream's subagent lines gives 1,859,987 against the transcripts' 2,294,981. An async agent's hand-back carries a `<usage><subagent_tokens>` total with no split; a forked `Skill` result carries no usage at all. Only the cockpit path reads a transcript dir: `measure()` (`src/measure.rs:169-211`) takes a transcript path the caller resolved, sums that file and `<session>/subagents/*.jsonl` into one figure with no own/subagent split, skips an unreadable `subagents/` dir silently (`:197-198`), and is called only by `report --cockpit` (`src/cli/report.rs:524-528`). Nothing in the binary builds a projects-dir path; `CLAUDE_CONFIG_DIR` is only kept in the worker env (`src/worker.rs:67`). The stub harness never emits a subagent line (`tests/stubs/stream.json:93`, `parent_tool_use_id` always null).

Because the collector ignores `parent_tool_use_id`, `start_context`, `peak_context` and every `tool_calls` row today mix the worker's own calls with its subagents'. The A/B lookup baselines were computed that way.

**Decisions taken 2026-10-13:**

- **Subagent usage is read from the worker's transcript dir after it exits**, by extending the reader in `src/measure.rs` so it returns the subagents' usage apart from the main file's, and by new code that builds the path: `<CLAUDE_CONFIG_DIR, else ~/.claude>/projects/<repo path with every "/" and "." as "-">/<session_id>/subagents/*.jsonl`. Four new `workers` columns, `sub_input`, `sub_cache_write`, `sub_cache_read`, `sub_output`, plus `subagents` (count). `quota::weighted` and every total in `report` include them; the per-role lines print the split (`own + subagents`). A worker whose session has no `subagents/` dir, or an empty one, gets zeros and `subagents = 0`; a dir that exists but cannot be read gets nulls and, in a live run, one `SubagentsUnread` event, never a failed run (under `--recount`, below, a warning line instead: the recount writes no events). *(Corrected 2026-10-13 after the adversarial pass: an earlier draft called this "the existing `measure()` reader", which has no split and no path builder.)* *(Accepted cost: this depends on Claude Code's transcript layout, which is not a contract; a layout change degrades to nulls and a warning line in the report. Rejected: the stream's own subagent lines, because their output count is a snapshot and output weighs 5; rejected: the hand-back total, because it has no split and a forked skill has none.)*
- **The collector tells main lines from subagent lines.** `start_context`, `peak_context` and `num_turns` count the worker's own lines only. `tool_calls` gains `in_subagent` (0/1), so lookup shares and `followup_reads` can be read with or without subagents; `report` prints them for the worker's own calls. *(Accepted cost: the stored A/B baselines (`ctx_share` 0.025, the lookup shares, `followup_reads`) mixed both and are not comparable with the own-only figures; the retro notes it and the next runs re-baseline. An earlier draft claimed the own-only figures matched "what the A/B research measured"; they do not, corrected 2026-10-13.)*
- **`factory report <run> --recount`** re-reads the stored streams under `runs/<id>/workers/` and the transcript dirs, and rewrites the token, context and `tool_calls` rows of that run. It exists so the two A/B rounds on this machine can be corrected in the store, and so a layout fix can be applied to past runs. It never touches `events`, `gates` or the run's docs. *(Accepted cost: a stored stream for a worker that Claude Code's transcript dir has since lost gets its own tokens only, and the report says so per worker.)*
- **`report --per-worker` prints tokens**: `weighted_own`, `weighted_sub`, `subagents`, `model_id` (FR-23), next to the lookup columns it prints today, and `--json --per-worker` carries the same fields (today `PerWorker` has no token field, `src/cli/report.rs:192-216`).

**Acceptance**: `factory report 024-20261012-e894 --recount` then `report` prints `weighted_tokens` within 1% of **18,465,008** (the workers' 16,170,027 plus the 2,294,981 the polish subagents weigh, `001-driver/ab/runs.md:233`, `:239`) with `cockpit_tokens` still 974,031 apart, and `018-20261011-6490` within 1% of **8,131,594** (6,078,688 plus 2,052,906, `001-driver/retro.md:105`, `:220`). *(Corrected 2026-10-13: the first draft set the targets at the run totals 19,439,039 and 8,750,823, which include the cockpit; `weighted_tokens` sums worker rows only, `src/cli/report.rs:443`.)* The stub scenario "polish with subagents" (a recording cut from the real `ddbb0927` stream plus two short `subagents/*.jsonl` fixtures) yields the four columns, `subagents = 2`, `in_subagent = 1` on the subagents' calls and `peak_context` from the main lines only; a build worker with no `subagents/` dir has zeros.

## 4. FR-22 — What the starting context is made of

**Today.** `Pack` holds a path, the prompt, the file list and the missing sections, no sizes (`src/pack.rs:54-65`). A slice pack is written as ordered sections: Slice, Block and answer (only when a block was answered, `:148-154`), PRD sections, Outline, Lookup, Contract, Autonomy, Inner loop (`src/pack.rs:145-178`), after a one-line `<!-- factory-pack files: … -->` header and a blank line; the polish pack has a second header line naming the run dir (`:385-388`); fix, checkpoint, polish and CI-fix packs have their own lists (`:199-249`, `:257-346`, `:355-424`, `:431-481`). Caps are constants: `OUTLINE_CAP` 8000, `DEF_CAP` 6000 (`:45`, `:47`). Only the file list is persisted (`workers.pack_files`, `src/worker.rs:406`); the pack files themselves stay on disk under `runs/<id>/packs/`. The arca-api round found builders starting at about 45k context, and that start accounts for about 46% of the build's cache reads (`001-driver/retro.md` § Why the build did not get cheaper). Nothing says what the 45k is: the pack's sections, Claude Code's own system prompt under `-p`, the repo's `AGENTS.md` and `CLAUDE.md` that Claude Code loads on its own, or the skill prompt. The owner's stated fear for the next experiments is cutting context blind and paying in quality.

**Decisions taken 2026-10-13:**

- **`workers.pack_parts`**, JSON, one entry per section the pack wrote: `[{"section": "slice", "chars": 9120}, …]`, measured when the pack is written, for every pack kind. `report` prints, per role, the mean chars per section and the pack's total chars beside `start_context`, so the reader sees the pack's share of the start and the remainder that is Claude Code's own. No token estimate from chars: the ratio differs between prose and code, and a wrong estimate would be read as a measurement. *(Accepted cost: the remainder is inferred, not measured; the experiment that trims Claude Code's own load (`AGENTS.md`, settings) measures it by difference.)*

**Acceptance**: every worker row has `pack_parts` with one entry per section its pack actually wrote, and the entries' `chars` sum to the char count of the pack file's text after its header comment lines and the blank line that follows them; `report` prints the per-role section means; the stub's three roles show three different section lists.

## 5. FR-23 — The knobs a run used

**Today.** Model and effort per role come from one file, `<config dir>/config.toml` (`src/config.rs:69-101`; the dir resolves `$FACTORY_CONFIG_DIR`, `$XDG_CONFIG_HOME/factory`, `~/.config/factory`, `src/paths.rs:75-78`), defaults `opus`, `high`, budget 30M (`src/config.rs:11-13`). Build reads it at `src/scheduler.rs:733`, checkpoint at `src/checkpoint.rs:324`, fix at `:645`, polish at `src/closeout.rs:266`, and CI fix reuses the fix role (`:1581`). `factory run` takes only `--budget` and `--foreground` (`src/cli/run.rs:27-37`); no flag, env or project file sets a model. The `runs` row stores the budget and nothing else about the configuration (`src/db.rs:17-94`). `workers.model` and `effort` are the configured strings (`src/worker.rs:396-405`); the model id the API actually answered with is parsed from `message.model` and dropped (`src/stream.rs:47`). Lanes come from the docs index (`src/docs.rs:197`). In run A of the arca round, one subagent ran on Sonnet and nobody knew until its meta file was read.

**Decisions taken 2026-10-13:**

- **A project scope: `docs/project.toml`**, with `[workers.<role>] model`, `effort` and `[run] budget`, overriding the user file key by key, read from the repo the run targets. Unknown keys warn as today (`src/config.rs:103-125`). The file is read when present; this PRD creates none. PRD-002 already agreed on `docs/project.toml` as the project's factory file and adds its own keys there later (§11). *(Accepted cost: PRD-002's migration must leave these tables alone. Rejected: a `.factory/config.toml`, a second project file PRD-002 would then have to merge; rejected: user scope only, because a per-stack setting (a Go project on a small pack, a Laravel project with its skills loaded) has nowhere to live.)*
- **The run row records what it resolved.** `runs.knobs`, JSON, written at run start: per role `{model, effort, source}` with `source` one of `default`, `user`, `project`; `budget` with its source; `lanes`; the `factory` version; the `claude --version` string. No variant files, no experiment ledger: an experiment is a settings change in the right scope, and the row says which scope. *(Accepted cost: two experiments in flight at once are told apart only by their hypothesis text.)*
- **`factory run NNN --hypothesis "<one line>"`** stores `runs.hypothesis`. The `/factory-deliver` skill passes it when the owner gives one. Optional; most runs have none.
- **`workers.model_id`** is the model string of the worker's first own assistant message, so a row says what answered, not only what was asked for.

**Acceptance**: a fixture whose `docs/project.toml` sets `[workers.polish] model = "sonnet"` makes the stub record `--model sonnet` for the polish call (`tests/stubs/claude:109-111`) and every other call `opus`; the run row's `knobs` says `polish.source = "project"` and `build.source = "default"`, with `lanes` and both versions filled; `report` prints the knobs block; `--hypothesis` text is in the row and in the retro (FR-25).

## 6. FR-24 — Quality signals per run, at zero tokens

**Today.** Gate results are stored per checkpoint attempt (`gates` rows, source `driver`, `src/checkpoint.rs:501-513`, `:565-577`) and per worker inner-loop run (source `worker`, `src/metrics.rs:491-503`); `report`'s `gate_*` keys count driver rows only (`src/cli/report.rs:402`). A fix commit is a `FixCommitted` event with its files (`src/checkpoint.rs:763-768`) and a sha on the fix worker's row (`:753`). CI produces `CiRed`, `CiRerun`, `CiFixSpawned` and `CiFixCommitted` events (`src/closeout.rs:1160-1164`, `:1278-1282`, `:1534`, `:1718`); `ci_cycles` counts the last (`src/cli/report.rs:424`); nothing counts red rounds or reruns. Polish returns a block with `STATUS`, `FIXED`, `RETRO`, `PR_BODY`, `DECISIONS`, `BLOCK` (`assets/contract-polish.md:20-26`) of which only `STATUS` is parsed (`src/stream.rs:126-141`). Decisions are `AD` entries in `agent-log.md`; `docs status --json` is parsed into `LogSummary { decisions, flagged, decide, blocks }` (`src/docs.rs:270-276`) and no driver path reads it. `score` is always empty (`src/cli/report.rs:420`). The owner chose on 2026-10-13 the signals the driver already sees and nothing that needs a model or the owner (§8 OPEN-1).

**Decisions taken 2026-10-13:**

- **A `FINDINGS` line in the polish return**: `FINDINGS high=<n> medium=<n> low=<n> fixed=<n> parked=<n>`, parsed like `STATUS`, stored as `runs.findings_high`, `findings_medium`, `findings_low`, `findings_fixed`, `findings_parked`. Added to `assets/contract-polish.md` and to the `/polish` skill's return. A missing line gives nulls and a `PolishFindingsMissing` event. The number is a trend, not an audit: a skill that mis-counts moves the trend, and the fix commits beside it keep it honest. *(Rejected: parsing the `AD` entries, prose that drifts, and findings fixed without an entry are invisible; rejected: fix commits only, which never see the defects polish catches before a commit.)*
- **`report` gains a quality block**, counts only, no composite score: `gate_red` (driver, exists), `worker_gate_red` (inner loop, exists as an extra key, `src/cli/report.rs:81`, `:464`; moves into the block), `fix_commits` (`FixCommitted` events), `ci_red_rounds` (`CiRed` events), `ci_reruns` (`CiRerun` events), the five `findings_*`, and `decisions`, `decide`, `blocks` read from `LogSummary` at ship and stored on the run row. *(Accepted cost: these say the builders left defects, not where; the per-slice split is the `gates` and `events` tables, by hand.)*

**Acceptance**: the stub polish recording with a `FINDINGS` line fills the five columns and `report` prints them; a recording without the line leaves nulls, emits the event and prints `findings: —`; the existing "red, red, green" gate scenario (`tests/checkpoints.rs:605`) reports `fix_commits = 2`, and the "red:test, green" CI scenario (`tests/closeout.rs:726`) reports `ci_red_rounds = 1`, `ci_reruns = 0`, `ci_cycles = 1` *(corrected 2026-10-13: the first draft named a "red, green" gate scenario that does not exist and expected `fix_commits = 1`)*; `decisions` equals the count `docs status --json` prints for the fixture.

## 7. FR-25 — `factory retro` drafts the numbers

**Today.** At ship the driver computes the report and writes twelve numeric keys into `retro.md`'s frontmatter (`src/closeout.rs:48-62`, `:575-590`, `:617-621`), bumping `ci_cycles` later per CI fix (`:1685-1695`); the polish worker writes the prose and must leave the frontmatter alone (`assets/contract-polish.md:12`, `src/pack.rs:394-402`). The prose never sees the numbers. PRD-001's retro and the two A/B write-ups were assembled by hand from `measure.py --retro` and a scratch script. PRD-001 §10 retires `measure.py` once `factory report` matches it within 2% (`001-driver/prd.md:141`); the subagent miss is why it does not match yet, and FR-21 closes that gap. PRD-002 FR-19 specifies a `retros` table filled from the twelve keys and a twelve-key `## Numbers` table in `retro.md`, with `factory report` unchanged (`002-docs-port/prd.md:132-136`).

**Decisions taken 2026-10-13:**

- **`factory retro <run>` writes a `## Numbers` section into the feature's `retro.md`**, between `<!-- factory:numbers -->` and `<!-- /factory:numbers -->` markers it owns, replacing what is there: a per-role table (own, subagents, weighted, minutes, turns), the knobs with their sources and the hypothesis, the quality block, the builders' pack composition, and a comparison with the same repo's last three runs that finished before this run started (never the run itself, so a rerun after `RunFinished` picks the same cohort), as weighted per slice shipped and weighted per changed line (`lines_added + lines_removed`, below); with no earlier run the block says so. The driver calls it at ship after `fill_retro`; the owner runs it by hand for any stored run, after a `--recount` or a schema fix. Rerunning it changes nothing else in the file. The twelve frontmatter keys stay, since PRD-002 reads them. *(Accepted cost: the section is a table, not judgment; the judgment stays the owner's and the polish worker's prose above it.)*
- **Changed lines are stored**: `runs.lines_added`, `lines_removed`, from `git diff --shortstat <base>..<head>` at ship, so cost per changed line is a column, not a retro-time shell call.
- **Comparison stays within the repo.** The section never prints a cross-repo ratio: the 54% against 86% of the two A/B rounds said more about the projects than about the driver.
- **`measure.py` and `weigh.py` are retired**: no QA guide or skill step names them after this ships. Deleting the old family is PRD-002's and the owner's (§12).

**Acceptance**: in the harness, after ship, `retro.md` holds the section and its per-role weighted figures equal `report --json --per-worker`'s summed per role; running `factory retro` again leaves the file byte-identical; a second fixture run on the same repo gets a comparison block naming the first, per slice and per changed line; on this machine, `factory retro 024-20261012-e894` reproduces run B's per-role rows in `001-driver/ab/runs.md:223-233` within 1%, with the polish row split into 1.95M own plus 2.29M subagents and the total 18,465,008, and a comparison block saying no earlier run in this repo. *(Corrected 2026-10-13: the first draft expected a comparison row with `018-20261011-6490`, which is icg-cloud, the cross-repo ratio this FR forbids; and a "corrected per-role table" that `runs.md` does not hold.)*

## 9. QA plan

**Gate**: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` *(declared in `index.md`)*
**Surface**: CLI (`factory report`, `factory report --recount`, `factory retro`, `factory run --hypothesis`), the `docs/project.toml` file, the `## Numbers` section of a feature's `retro.md`.
**Harness**: the stub harness in `tests/harness/mod.rs` (fixture repo, stub `claude` and `gh`, scenarios by plan file). ## 12. Non-goals

- **The learning loop** (event queue, deterministic ranking, keep/tune/cut verdicts, hypotheses checked after N runs) — a later PRD, once runs carry these signals. The `hypothesis` column (FR-23) is the only hook it leaves.
- **Turning any knob** — no change to the default models, effort, pack caps or the lookup hint here (the FR-23 fixture sets a model on purpose to prove the scope; a test, not a default). Each experiment is its own small PRD on a project, and adds the knob it needs if the knob does not exist yet (pack size and ctx on/off do not).
- **PRD-002's port and the deletion of the old skill family** — the `/polish` line in FR-24 and the `--hypothesis` pass-through in `skills/factory-deliver` (this repo, symlinked into `~/.claude/skills`) are the only skill edits. Burning the bridge (archiving `~/.claude/skills/*` and the Dropbox repo) is the owner's hand after PRD-002 ships.
- **No composite quality score.** Counts only; a score would be read as a verdict.
- **Not handled: a `factory grade` review worker** (a fixed-rubric score of the PR against the spec, about 0.3–0.5M tokens per run). Declined 2026-10-13: a model's score is noise as a verdict and the owner wants zero-token signals first. Revisit if the FR-24 counts stay flat while the owner's reviews find more defects.
- **Not handled: owner review signals** (overturned decisions, a two-question form at close). Declined 2026-10-13: it needs the owner every run. The `AD` entries stay in `agent-log.md`, so the count can be added later without losing history.
- **Not handled: post-merge churn and production bugs.** The truest quality signal, but delayed; it needs the `factory bugs` idea (`ideas.md`). Revisit when that idea graduates.
- **Not handled: variant files or an experiment ledger.** Declined 2026-10-13 (§8 OPEN-2). Revisit if two experiments ever run at once on one project.
- **Not handled: subagent usage read from the stream when the transcript dir is missing.** Accepted 2026-10-13: never seen; the stream's output count is a snapshot and would print a floor that reads like a total. Revisit if a `SubagentsUnread` event ever fires.
- **Not handled: a per-turn context series per worker.** `start_context`, `peak_context`, `num_turns` and `tool_calls.result_chars` by kind already give turns × context; a series would be a figure with no decision behind it. Revisit if an experiment needs the growth curve.
- **Not handled: subagent `model_id`.** A subagent's model varies per call and the skills choose it; FR-23 records the worker's own. Revisit if a polish experiment sets subagent models.
- **Not handled: advisor tokens.** Separate idea in `ideas.md`; the API reports them apart from usage.
